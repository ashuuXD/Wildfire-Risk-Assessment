# Model Card

## Model Details
- **Task**: Binary classification -- will a wildfire occur in a grid cell
  during the next 7-day prediction window?
- **Models compared**: Logistic Regression, Random Forest, XGBoost (or
  scikit-learn `GradientBoostingClassifier` fallback if XGBoost is not
  installed).
- **Training data**: Synthetic demonstration dataset generated by
  `generate_demo_data.py` (fixed seed 42), 5 simulated years, weekly
  resolution, ~0.4-degree grid over Central India.
- **Split**: Chronological -- earliest 70% train / next 15% validation /
  final 15% test.

## Illustrative Results (synthetic demo data, one run, seed=42)
| Model | Accuracy | Precision | Recall | F1 | ROC-AUC | PR-AUC |
|---|---|---|---|---|---|---|
| Random Forest | 0.845 | 0.105 | 0.714 | 0.184 | 0.853 | 0.129 |
| Logistic Regression | 0.827 | 0.098 | 0.739 | 0.173 | 0.854 | 0.123 |
| Gradient Boosting (XGBoost) | 0.847 | 0.106 | 0.705 | 0.185 | 0.850 | 0.120 |

**These numbers describe performance on synthetic data only** and are
regenerated each time the pipeline runs (exact values may vary slightly by
environment/library version even with a fixed seed). They are illustrative
of the pipeline working correctly end-to-end, not evidence of real-world
predictive skill.

## Interpreting These Metrics
- **Recall ~0.7-0.74**: the models catch roughly 70-74% of synthetic fire
  events in the test period.
- **Precision ~0.10**: at the default 0.5 probability threshold, about 1
  in 10 positive predictions is a true fire event on this deliberately
  imbalanced synthetic target -- expected and typical for rare-event
  classification without threshold tuning; the risk-category thresholds
  (Low/Moderate/High/Extreme) are a more actionable way to consume the
  probability output than a hard 0/1 classification.
- **ROC-AUC ~0.85**: models separate fire/no-fire weeks substantially
  better than chance (0.5) on this synthetic data.
- **Balanced accuracy ~0.78**: the average of each class's own recall
  (e.g. ~83% of no-fire weeks and ~74% of fire weeks correctly identified
  for Logistic Regression). This is the more honest accuracy figure for an
  imbalanced target -- plain accuracy alone can look high or low purely as
  an artifact of class frequency, whereas balanced accuracy weights both
  classes equally. The dashboard shows both a raw-count confusion matrix
  and a row-normalized (%) version side by side: the raw counts differ
  enormously in scale simply because fire weeks are rare in the test set
  (that scale gap **is** the class imbalance, not an error), while the
  normalized view puts both classes on a common 0-100% scale for direct
  comparison.

## Intended Use
Software prototype / capstone demonstration only. **Not** validated,
operational, or suitable for real wildfire detection, monitoring, or
emergency-response decisions.

## Explainability
SHAP (if installed) or a documented fallback (built-in feature importance
/ permutation importance / logistic-regression coefficients) is used to
surface the top contributing features per model and per grid cell. See
`explainability.py` and `08_Documentation/METHODOLOGY.md`.

## Known Limitations
- Trained and evaluated exclusively on synthetic data (see
  `01_Research/SCOPE_AND_LIMITATIONS.md`).
- Risk thresholds are uncalibrated prototype values.
- No causal interpretation of feature importance is valid.
- Real-world validation with NASA FIRMS / weather / satellite data is
  future work.
